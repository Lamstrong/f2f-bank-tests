# F2F Bank - Автоматизированное E2E тестирование (Playwright)

Репозиторий содержит набор сквозных end-to-end (E2E) тестов для веб-приложения **F2F Bank** (сервис переводов между пользователями по номеру телефона в стиле СБП).

---

## 🛠 Стек технологий

- **Тестовый фреймворк:** [Playwright](https://playwright.dev/) (TypeScript)
- **Паттерн проектирования:** Page Object Model (POM)
- **Менеджер пакетов и рантайм:** Bun / Node.js
- **Тестируемое приложение:**
  - Frontend: Vue 3 (Vite, Pinia)
  - Backend: FastAPI (Python 3.12, SQLAlchemy)
  - Database: PostgreSQL 16
  - Reverse Proxy: Nginx

---

## 🚀 1. Запуск приложения

Для развертывания приложения используется Docker Compose.

### Предварительные требования:
- Установленный и запущенный **Docker Desktop** (Engine running).
- Свободные порты `80` и `443` на локальной машине.

### Запуск сервисов:
```bash
docker compose up -d --build
```
*Команда собирает фронтенд, запускает бэкенд на FastAPI, базу данных PostgreSQL и Nginx proxy на порту 80.*

### Проверка доступности:
Откройте в браузере: [http://localhost](http://localhost) — откроется страница входа F2F Bank.

### Остановка приложения и сброс данных:
```bash
# Обычная остановка:
docker compose down

# Полная остановка с очисткой данных БД:
docker compose down -v
```

## 🧪 2. Запуск тестов

### Установка зависимостей:
```bash
bun install
# или через npm:
npm install
```

### Установка браузера Chromium для Playwright:
```bash
bunx playwright install chromium
# или через npx:
npx playwright install chromium
```

### Запуск тестов:
```bash
# Запуск всех тестов в headless-режиме:
bun run test
# или:
npx playwright test

# Запуск в интерактивном UI-режиме (с возможностью пошаговой отладки):
bun run test:ui
# или:
npx playwright test --ui

# Запуск с отображением браузера:
bun run test:headed
# или:
npx playwright test --headed
```

### Просмотр отчета о прохождении тестов:
```bash

# или:
npx playwright show-report
```

## 📋 3. Описание написанных сценариев и их приоритеты

Все тесты структурированы по модулям и имеют четкую градацию приоритетов:
- 🔴 **Критический (Critical)** — блокирующий базовый бизнес-функционал (регистрация, вход, переводы, пополнение).
- 🟠 **Высокий (High)** — ключевой позитивный и негативный функционал, безопасность сессий, корректность баланса.
- 🟡 **Средний (Medium)** — валидация форм, защита маршрутов, сброс состояний.
- 🟢 **Низкий (Low)** — вспомогательные интерфейсные проверки.

### Матрица тест-кейсов

| ID | Модуль | Приоритет | Что тестируется | Входные данные | Ожидаемый результат |
|---|---|---|---|---|---|
| **AUTH-01** | Auth | 🔴 Критический | Успешная регистрация нового пользователя | Валидные уникальные Name, Surname, Email, Password | Уведомление об успехе, автоматический редирект на `/login` |
| **AUTH-02** | Auth | 🔴 Критический | Авторизация зарегистрированного пользователя | Корректные Email и Password | Редирект на главную `/`, отображение панели навигации и баланса |
| **AUTH-03** | Auth | 🟠 Высокий | Ошибка входа с неверным паролем | Валидный Email, неверный Password | Уведомление «Login failed», пользователь остается на `/login` |
| **AUTH-04** | Auth | 🟠 Высокий | Ошибка входа с несуществующим пользователем | Случайный незарегистрированный Email | Уведомление «Login failed» |
| **AUTH-05** | Auth | 🟠 Высокий | Повторная регистрация на уже занятый email | Email уже зарегистрированного пользователя | Ошибка «User with this email already exists» |
| **AUTH-06** | Auth | 🟡 Средний | Валидация незаполненных полей формы логина | Пустые поля Email / Password | Отправка блокируется валидацией, URL не меняется |
| **AUTH-07** | Auth | 🟡 Средний | Валидация незаполненных полей при регистрации | Заполнено только одно поле (Name) | Форма не отправляется, переход на `/login` заблокирован |
| **AUTH-08** | Auth | 🟠 Высокий | Выход из системы (Logout) | Авторизованный пользователь кликает кнопку выхода | Редирект на `/login`, скрытие приватных элементов навигации |
| **AUTH-09** | Auth | 🟡 Средний | Защита закрытых маршрутов от неавторизованного доступа | Прямой переход по URL `/transactions` гостем | Автоматический редирект на `/login` |
| **BAL-01** | Balance | 🔴 Критический | Пополнение баланса через модальное окно | Положительная сумма (например, 1500.50) | Баланс увеличивается в Header и на странице, создается транзакция |
| **BAL-02** | Balance | 🟠 Высокий | Синхронизация баланса между разделами | Пополнение счета, переходы Главная ⇄ Профиль ⇄ Транзакции | Единое актуальное значение баланса на всех экранах |
| **BAL-03** | Balance | 🟡 Средний | Отмена пополнения баланса | Ввод суммы и клик по кнопке «Cancel» | Модальное окно закрывается, баланс остается прежним |
| **BAL-04** | Balance | 🟡 Средний | Валидация нулевой суммы при пополнении | Ввод суммы `0` в модальном окне | Модальное окно не отправляет запрос, баланс не изменяется |
| **TRF-01** | Transfer | 🔴 Критический | Успешный перевод средств по номеру телефона | Достаточный баланс, номер `+7 999 888-77-66`, сумма, назначение | Экран «Transfer completed», списание средств с баланса |
| **TRF-02** | Transfer | 🔴 Критический | Перевод при недостаточном балансе | Баланс 0, попытка перевода на сумму 500 | Ошибка «Transfer failed. Check your balance.», баланс не меняется |
| **TRF-03** | Transfer | 🟠 Высокий | Валидация формата телефона (без знака `+`) | Номер `89991234567` | Ошибка «Must start with + and country code...», форма не отправляется |
| **TRF-04** | Transfer | 🟠 Высокий | Валидация длины телефона (слишком короткий/длинный) | Номер `+799912` (< 10 цифр) | Ошибка «Phone must contain 10–15 digits» |
| **TRF-05** | Transfer | 🟠 Высокий | Валидация нулевой суммы перевода | Сумма `0` | Сообщение «Amount must be greater than zero», отправка блокируется |
| **TRF-06** | Transfer | 🟡 Средний | Очистка полей формы по кнопке Cancel | Заполненная форма перевода, клик «Cancel» | Поля очищаются к исходному состоянию |
| **TRF-07** | Transfer | 🟠 Высокий | Фиксация списания в истории транзакций | Успешный перевод средств | Запись с суммой перевода появляется первой в списке транзакций |
| **TX-01** | Transactions | 🟠 Высокий | Отображение пустого состояния истории | Новый аккаунт без совершенных операций | Отображение блока «No transactions yet», таблица пуста |
| **TX-02** | Transactions | 🟠 Высокий | Отображение списка операций | Пополнение + перевод | Корректное количество строк и отображение сумм |
| **TX-03** | Transactions | 🟡 Средний | Проверка соответствия заголовков колонок выводимым данным | Выполненная операция | Выявление дефекта UI с перепутанными колонками Type и Status |
| **PROF-01** | Profile | 🟠 Высокий | Отображение персональных данных пользователя | Авторизованный пользователь с известными Name, Surname, Email | Корректный вывод данных в карточке `/profile` |
| **PROF-02** | Profile | 🟡 Средний | Сохранение сессии и данных при перезагрузке страницы | Открытый профиль, вызов `page.reload()` | Данные сохраняются, сессия не сбрасывается |

## 🏗 4. Архитектура автотестов (3-слойная модель)

Проект строго следует 3-слойной архитектуре Playwright:

```
СЛОЙ 3: SPEC (Файлы тестов: tests/*.spec.ts)
  - Знает бизнес-логику процесса, сценарии и входные данные.
  - Получает пейлоад от фабрик данных (Слой 2).
  - Передает параметры в фикстуры и методы POM, выполняет финальные assertions.

СЛОЙ 2: FIXTURES & FACTORIES (tests/fixtures/*, tests/factories/*)
  - tests/factories/user.factory.ts: фабрика генерации данных пользователей (createUserData).
  - tests/factories/transfer.factory.ts: фабрика параметров перевода (createTransferData).
  - tests/fixtures/auth.fixture.ts: фабричные функции инициализации POM и создания изолированных пользовательских сессий с преднастроенным балансом.

СЛОЙ 1: POM (tests/pages/*.pom.ts, tests/components/*.pom.ts)
  - Чистая UI-логика, селекторы и интерактивные методы.
  - Полная изоляция от тестовых данных: методы принимают строго типизированные DTO на лету.
  - Разделение методов действий и проверок с префиксами expect...
```

Структура каталогов тестового модуля:
```
tests/
├── components/
│   ├── AddBalanceModalComponent.pom.ts   # [Слой 1] Компонент модального окна пополнения баланса
│   └── HeaderComponent.pom.ts            # [Слой 1] Компонент навигационной шапки и отображения баланса
├── factories/
│   ├── transfer.factory.ts               # [Слой 2] Фабрика тестовых данных для переводов
│   └── user.factory.ts                   # [Слой 2] Фабрика тестовых данных пользователей
├── fixtures/
│   └── auth.fixture.ts                   # [Слой 2] Фикстуры-фабрики для сессий и страниц
├── pages/
│   ├── BasePage.pom.ts                   # [Слой 1] Базовый класс страниц
│   ├── LoginPage.pom.ts                  # [Слой 1] Страница входа (/login)
│   ├── ProfilePage.pom.ts                # [Слой 1] Страница профиля пользователя (/profile)
│   ├── RegisterPage.pom.ts               # [Слой 1] Страница регистрации (/register)
│   ├── TransactionsPage.pom.ts           # [Слой 1] Страница истории операций и пополнения (/transactions)
│   └── TransferPage.pom.ts               # [Слой 1] Главная страница с формой перевода СБП (/)
├── auth.spec.ts                          # [Слой 3] Тесты авторизации и регистрации
├── balance.spec.ts                       # [Слой 3] Тесты пополнения счета и синхронизации баланса
├── profile.spec.ts                       # [Слой 3] Тесты страницы профиля
├── transactions.spec.ts                  # [Слой 3] Тесты истории операций
└── transfer.spec.ts                      # [Слой 3] Тесты переводов по номеру телефона
```

## 🐛 5. Найденные баги и замечания к приложению

Подробное описание всех найденных дефектов находится в файле [NOTES.md](file:///c:/Users/dev7/Desktop/ozonB/NOTES.md).

**Краткая сводка основных багов:**
1. **[Backend] Отсутствие зачисления средств получателю при переводе:** в `user_service.py` создается только операция списания (`WITHDRAWAL`) для отправителя. Операция зачисления (`DEPOSIT`) получателю не создается, а переданный `purpose` игнорируется.
2. **[Frontend] Перепутаны колонки таблицы транзакций:** в `TransactionsTable.vue` колонка «Operation Type» отображает статус (`completed`), а колонка «Operation Status» отображает тип (`deposit`/`withdrawal`).
3. **[Frontend] Некорректные атрибуты `name`:** в `RegisterView.vue` email имеет `name="login"`, а пароль `name="Type your password"`.
4. **[Frontend/Auth] Logout не обращается к бэкенду:** кнопка выхода не вызывает API эндпоинт `/api/auth/logout`.
5. **[Frontend/UI] Отсутствие обратной связи при невалидном пополнении баланса:** при вводе 0 или отрицательного числа модальное окно не выдает ошибку.
